Metodologi Pengembangan
Metode: Design Science Research (DSR)

Proyek ini menggunakan metode Design Science Research yang terdiri dari 6 tahap sistematis untuk merancang, membangun, dan mengevaluasi artefak sistem informasi.


Alasan Ilmiah Memilih DSR:
  • Penelitian berfokus pada perancangan artefak (sistem monitoring), bukan pengujian teori murni
  • Masalah yang diselesaikan bersifat design problem — membutuhkan solusi teknologi baru
  • DSR menyediakan kerangka evaluasi yang ketat: metrik teknis dan penerimaan pengguna
  • Sesuai dengan nature proyek yang menghasilkan software sebagai artefak penelitian
  • Mendukung iterasi antara desain dan evaluasi, berbeda dari waterfall murni

Strategi Adaptasi Arsitektur
Arsitektur SCINetwork dirancang modular sehingga perubahan requirement dapat diakomodasi tanpa refaktor besar-besaran.

Prinsip desain yang membantu:

  • Layered architecture — handler → service → repository terpisah
  • Dual-database — MySQL untuk data operasional, ClickHouse untuk log (masing-masing bisa di-ALTER independen)
  • ML sidecar — Modul ML terpisah dari backend utama, komunikasi via HTTP API
  • Docker Compose — Setiap service dikelola independen, mudah rebuild
  • RBAC permission-based — Penambahan fitur baru cukup tambah permission baru tanpa ubah middleware

Poin I
Identifikasi Masalah Utama
Kendala Terbesar
🔧
1. Teknis: ICMP Ping Membutuhkan Privilege

Go ICMP ping membutuhkan CAP_NET_RAW. Di Docker harus ditambahkan cap_add: NET_RAW. Di bare-metal perlu run as root atau setcap.

🔧
2. Teknis: SNMP Tidak Aktif di Semua Perangkat

Beberapa perangkat jaringan kantor belum mengaktifkan SNMP, sehingga fallback ke ping/HTTP diperlukan. Mitigasi: SNMP diaktifkan bertahap.

📊
3. Keterbatasan Data: ML Training Awal

Model Isolation Forest membutuhkan volume data monitoring yang cukup. Pada awal deployment, data historis belum tersedia. Solusi: data simulasi + daily re-training otomatis.

🔗
4. Integrasi: Multi-database Consistency

Menjaga konsistensi antara MySQL (data operasional) dan ClickHouse (log). Solved: write-through pattern di service layer.
